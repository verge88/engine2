# engine2

**engine2 v1.0** — экспериментальный игровой runtime и 3D-рендерер на **C++20 / OpenGL 3.3 Core**. Есть glTF 2.0, текстурные PBR-материалы, HDR Image-Based Lighting, несколько точечных источников света, SSAO и отсечение невидимых объектов. Это пока **не полноценный production-движок и не готовый фотореализм**: нет редактора, полноценной физики, аудио и скриптов.

## Возможности

- GLFW окно, цикл приложения, FPS-камера, управление мышью и клавиатурой.
- **Scene runtime (v1.0):** сущности с generation handles (защита от stale references), произвольные имена, дочерние объекты и локальные/world трансформации, проверки циклов, переподчинение с сохранением world matrix, рекурсивное удаление, отключение видимости родительских объектов. Компоненты `MeshRenderer`, `PointLight`, `RigidBody`. Рендерер и точечные источники получают данные из Scene, включая при загрузке glTF.
- **Фиксированный игровой шаг:** численное обновление физических тел на 60 Гц с аккумулятором времени и максимум 8 шагами на кадр; гравитация и упрощённое столкновение сферы с горизонтальной плоскостью. Для воспроизводимых демонстраций: `--physics-demo 1 --sim-dt 0.1`. Это **не полноценная система физики**, нет столкновений объектов друг с другом, непрерывного обнаружения столкновений и joint constraints.
- Индексированные меши, процедурная геометрия, трансформации, локальные AABB.
- Импорт **glTF 2.0 (.gltf/.glb)**: меши, UV0, иерархия узлов, инстансы, генерация нормалей и тангентов.
- Текстурные PBR-материалы: base color (sRGB), metallic/roughness, normal, AO, emissive.
- **glTF alpha modes:** `OPAQUE`, `MASK` (порог отсечения и текстурный alpha-канал в PBR, shadow map и SSAO) и `BLEND` (depth test + сортировка мешей по расстоянию + смешивание цветов в линейном HDR-буфере). Прозрачные объекты рисуются после непрозрачных; `MASK` сохраняет глубину и отбрасывает непрозрачные тени по силуэту.
- **Cook–Torrance GGX**: направленный солнечный свет с **3 каскадами PCF-теней**, до 8 движущихся точечных источников с обратноквадратичным затуханием.
- **Каскадные тени от солнца (v0.7):** 0, 1 или 3 каскада из глубинного OpenGL 3.3 texture-array (1536×1536 на слой). Схема разделения глубины 60% logarithmic / 40% linear, привязка к сетке текселей, отдельное отбрасывание shadow casters и 3×3 PCF. Дальность солнечных теней настраивается независимо от дальности камеры. `--cascade-debug 1` визуально помечает каскады.
- **Точечные тени (v0.6):** до **2** из этих источников создают собственные **кубические карты глубины** с 6 направлениями каждая (256×256 на грань), радиальным сравнением расстояний и 12-tap PCF. Маскированные glTF-материалы отбрасывают тени по alpha-cutoff; BLEND не отбрасывают тени.
- **HDR IBL**: панорама Radiance `.hdr` или процедурный небосвод, diffuse irradiance, GGX specular prefilter, split-sum BRDF LUT.
- **Temporal Anti-Aliasing (v0.8):** 8-точечный Halton(2,3) jitter камеры, HDR history ping-pong в 16-битном float, восстановление мировых координат по depth texture и reprojection предыдущей view-projection матрицей. Depth-disocclusion rejection и ограничение исторического цвета по 3×3 окрестности уменьшают шлейфы. Фильтрация выполняется до bloom и ACES. Каскадные карты солнечных теней вычисляются по **недрожащей** матрице камеры; при изменении разрешения, переключении TAA и резком перемещении история сбрасывается.
- **SSAO**: полурезолюционный геометрический проход (позиция/нормаль в координатах камеры), 16 hemisphere samples и edge-aware blur; влияет на непрямое освещение, а не на прямой свет.
- **Frustum culling**: шесть плоскостей камеры проверяются против трансформированных AABB; shadow casters проверяются отдельно во фрустуме каждого каскада солнца, чтобы не терять тени от объектов вне кадра.
- **Автоматическая HDR-экспозиция (v0.9):** выделенный GPU-проход 128×128 вычисляет логарифм яркости, а цепочка mipmap усредняет его до 1×1. CPU адаптирует экспозицию экспоненциально с учётом реального `deltaTime` (в среднем по геометрической яркости). Параметры `--auto-exposure`, `--exposure-key`, `--exposure-speed`; прежний `--exposure` остаётся ручной экспокоррекцией (множителем).
- **Многоуровневый bloom (v0.9):** пять отдельных HDR RGBA16F буферов 1/2—1/32 размера, soft-knee threshold, 13-tap downsample и аддитивный tent upsample. Яркость и порог настраиваются отдельно: `--bloom` и `--bloom-threshold`.
- HDR framebuffer RGBA16F, TAA-resolved HDR перед bloom/тональной компрессией, ACES tonemapping.
- PPM-screenshot, диагностические счётчики draw calls, CTest с базовыми проверками пикселей и математики.

Внешние зависимости: GLFW, glad, GLM, tinygltf/stb. Код GPU-проходов, фильтров, PBR-шейдеров, отбраковки и приложения находится в `engine2`.

## Сборка

Требуются: CMake 3.24+, C++20, Python 3, Git, OpenGL 3.3 Core, интернет для первой настройки CMake. На Ubuntu потребуются `libgl1-mesa-dev libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev xvfb`.

```bash
git clone https://github.com/verge88/engine2.git
cd engine2
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/engine2
```

На Windows: `cmake -S . -B build`, `cmake --build build --config Release`, запуск `build/Release/engine2.exe`; на macOS требуется OpenGL 3.3 Core. Каталог `shaders` копируется рядом с бинарником.

## Игровые сущности и физический пример

Пример запуска демонстрации одной падающей сферы. Вся основная сцена теперь создаётся как набор сущностей; объект имеет `MeshRendererComponent` и `RigidBodyComponent`, а свет — отдельный `PointLight` компонент.

```bash
# Динамическая сцена с гравитацией и простой горизонтальной коллизией
./build/engine2 --physics-demo 1 --stats

# Воспроизводимый фиксированный шаг моделирования для тестов кадров
./build/engine2 --physics-demo 1 --sim-dt 0.1 --frames 12 \
  --stats --screenshot physics.ppm
```

Основные API находятся в `include/engine2/Scene.hpp`: `createEntity`, `destroyEntity`, `setParent`, `setLocalTransform`, `setRenderer`, `setPointLight`, `setRigidBody`, `advance`, `renderItems`, `pointLights`. Компоненты хранят не владеющие указатели на GPU-меши, поэтому хранилище ресурсов должно переживать `Scene`.

## Пример прозрачных glTF-материалов

Для проверки добавлены три тестовые сцены с одинаковой геометрией и разными режимами альфа-канала. Пиксели сравниваются автоматически в CI.

```bash
./build/engine2 --model tests/data/alpha-opaque.gltf --ssao 0 --lights 0
./build/engine2 --model tests/data/alpha-mask.gltf --ssao 0 --lights 0
./build/engine2 --model tests/data/alpha-blend.gltf --ssao 0 --lights 0
```

## Параметры

```bash
# Включённый по умолчанию SSAO и 3 движущихся локальных источника
./build/engine2

# Внешние модель и окружение, 6 цветных огней
./build/engine2 --model assets/scene.glb --environment assets/studio.hdr --lights 6 --point-shadows 2

# Отключить затенение окружения или все точечные источники
./build/engine2 --ssao 0 --lights 0

# Сохранить подсветку, но отключить тени точечных источников
./build/engine2 --lights 3 --point-shadows 0

# Детерминированная проверка разных настроек теней (время анимации = 0)
./build/engine2 --lights 1 --point-shadows 1 --light-time 0 --frames 2 --stats

# Каскады солнечных теней, дистанция и режим отладки (цветные зоны)
./build/engine2 --sun-cascades 3 --sun-distance 95 --cascade-debug 1

# Сравнение с одиночной картой или полностью без солнечных теней
./build/engine2 --sun-cascades 1
./build/engine2 --sun-cascades 0

# Сравнить TAA с выключенным сглаживанием
./build/engine2 --taa 1 --taa-weight 0.9
./build/engine2 --taa 0

# Отключить frustum culling для отладки геометрии
./build/engine2 --culling 0

# Автоэкспозиция включена по умолчанию; можно настроить среднюю
# целевую яркость и скорость адаптации или включить полностью ручной режим
./build/engine2 --auto-exposure 1 --exposure-key 0.18 --exposure-speed 1.5
./build/engine2 --auto-exposure 0 --exposure 0.85

# Многоуровневый bloom и мягкий порог выделения ярких областей
./build/engine2 --bloom 0.3 --bloom-threshold 1.2

# Экспозиция, bloom, статистика и сохранение PPM
./build/engine2 --exposure 0.75 --bloom 0.25 --frames 2 --stats --screenshot frame.ppm

# Автоматические тесты
ctest --test-dir build --output-on-failure
```

Допустимые диапазоны: `--physics-demo` 0|1 (только процедурная сцена), `--sim-dt` 0..0.25 секунды; `--auto-exposure` 0|1, `--exposure-key` 0.02..1, `--exposure-speed` 0..12, `--bloom-threshold` 0.05..10, `--taa` 0|1 (по умолчанию включён), `--taa-weight` 0..0.98, `--sun-cascades` 0|1|3, `--sun-distance` 5..150, `--cascade-debug` 0|1, `--lights` 0..8, `--point-shadows` 0..2 (оба целые), `--light-time` 0..1000000 секунд, `--ssao` и `--culling` 0|1, `--exposure` 0.05..16, `--bloom` 0..2.

## Ограничения версии 1.0

- **Scene — компактная компонентная система, а не archetype ECS:** нет сериализации, редактора, системы скриптов, параллельного update, поисковых запросов по компонентам или полноценных игровых событий. Иерархия glTF в runtime пока импортируется как готовые world-матрицы отдельных primitives; исходные parent-child связи glTF не восстанавливаются.
- **Физический прототип** поддерживает только однотипную гравитацию и столкновение каждого сферического тела с фиксированной горизонтальной плоскостью, без контактов между сущностями и без детектирования реальных Mesh collider. Физические тела должны быть корневыми; фиксированный шаг ограничен восемью итерациями за кадр.
- **Тени только от первых 0–2 точечных источников:** остальные точечные огни освещают сцену без теней. Дополнительные карты включают 6 проходов на источник; при движении всех огней карты перерисовываются каждый кадр. Тени из PCF остаются приближёнными. Динамическое выделение теневых ресурсов и caching пока отсутствуют.
- SSAO не учитывает normal maps и является экранным приближением, не глобальным освещением; возможно появление артефактов на границах.
- Расчёт IBL основан на статическом HDR-окружении. Нет трассировки лучей, SSR, настоящего GI и motion vectors объектов.
- Импорт glTF ограничен TRIANGLES и UV0 без анимаций, скининга, sparse accessors и extensions.
- Прозрачные glTF `BLEND`-поверхности отсортированы **по центру меша**, поэтому пересекающиеся треугольники внутри мешей, сложные слои и самопересечения могут отображаться некорректно (order-independent transparency пока нет). `BLEND` не пишет глубину, не отбрасывает тени и не участвует в SSAO; `MASK` учитывается всеми тремя проходами. Материалы без `MASK`/`BLEND` остаются полностью непрозрачными.
- Frustum culling CPU не использует иерархические деревья/батчинг: одна проверка на экземпляр. Статистика считает только переданные в API `RenderItem` и draw calls из shadow/PBR-проходов.
- **Текущая автоэкспозиция считывает одну 1×1 R16F mip-точку с GPU на CPU каждый кадр:** это простая реализация с возможной синхронизацией CPU/GPU. Для больших игр потребуется асинхронное чтение (PBO/fence) или полностью GPU-resident экспозиция. При резкой смене освещения адаптация намеренно плавная.
- Многоуровневый bloom выполняет несколько полноэкранных проходов; число слоёв фиксировано (5), нет dirt mask, lens flare и physically based glare.
- **TAA использует репроекцию только от движения камеры, без motion vectors объектов.** Анимированная геометрия, прозрачные поверхности, быстро движущиеся источники света и резкие изменения shading могут оставлять артефакты/ghosting. У неба пока нет отдельной исторической репроекции, поэтому TAA для него пропускается. Это не полная реализация TAA уровня крупного игрового движка.
- Три солнечных каскада обновляются каждый кадр: это до трёх полноразмерных проходов теней. На расстояниях дальше `--sun-distance` тени от солнца не рисуются. Нет плавного смешивания границ каскадов, возможны переходы качества и shadow acne; динамическая оптимизация и caching пока отсутствуют.
- Точечные кубические карты глубины **не поддерживают полупрозрачные BLEND-тени** и используют alpha-test только для MASK. Невозможны мягкие физически точные тени от площади источника.
- Производительность различается по драйверам. Тесты запускаются в Linux через программный OpenGL, визуальное сравнение пока не эталонное.
